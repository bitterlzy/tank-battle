# Java Swing 简易坦克大战开发任务书

请使用 Java 17、Swing、Socket、Gson 和 Maven，开发一个适合高校 Java 课程、能够在约 6 小时实践课内完成的简易网络坦克大战游戏。

## 1. 项目要求

采用客户端/服务器架构。

项目分为 `server` 和 `client` 两个独立文件夹，分别使用独立的 Maven 配置。

服务端由 AI 完整实现，学生只负责客户端。

## 2. 游戏功能

只实现以下功能：

1. 客户端输入玩家昵称、服务器 IP 和端口。
2. 点击连接按钮后连接服务器。
3. 使用 WASD 控制自己的坦克移动。
4. 使用不同颜色区分不同玩家。
5. 多个客户端能够实时看到彼此的坦克位置变化。
6. 界面显示玩家昵称、在线玩家列表和网络连接状态。
7. 连接失败或服务器断开时显示提示。

不实现射击、炮弹、碰撞伤害、地图破坏、游戏胜负、复杂房间系统等功能。

## 3. 技术要求

- Java 17。
- Java Swing。
- Socket 和 ServerSocket。
- Gson 处理 JSON。
- Maven 管理依赖。
- 使用 JPanel 和 Graphics2D 绘制游戏画面。
- 使用 Swing Timer 定时刷新界面。
- 使用独立线程处理网络接收，不能阻塞 Swing 界面线程。

## 5. 客户端类的职责

### ClientMain.java

程序入口，启动 Swing 窗口。

### GameFrame.java

创建主窗口、登录区域、昵称输入框、服务器地址输入框、连接按钮、网络状态和玩家列表。

### GamePanel.java

继承 JPanel，绘制游戏地图和所有坦克，处理 WASD 键盘输入，并刷新游戏画面。

地图使用简单的网格或绿色背景即可，不需要外部图片素材。

### Tank.java

保存玩家 ID、昵称、坐标、方向和颜色等基本属性。

提供必要的构造方法、getter 和 setter。

### NetworkClient.java

负责连接服务器、发送 JSON 消息、接收服务器广播、处理断线和关闭连接。

网络接收必须运行在独立线程中，更新 Swing 组件时遵循 EDT 线程规则。

## 6. 简单通信协议

使用 UTF-8 编码的 JSON 文本，通过 TCP 传输，每条消息以换行符 `\n` 结束。

客户端连接后发送：

```json
{
  "type": "join",
  "playerName": "张三"
}
```

坦克移动后发送：

```json
{
  "type": "move",
  "x": 120,
  "y": 160,
  "direction": "up"
}
```

服务器向客户端广播所有玩家的状态：

```json
{
  "type": "players",
  "players": [
    {
      "playerId": 1,
      "playerName": "张三",
      "x": 120,
      "y": 160,
      "direction": "up"
    },
    {
      "playerId": 2,
      "playerName": "李四",
      "x": 240,
      "y": 200,
      "direction": "left"
    }
  ]
}
```

以上仅为示例，正式代码必须保持字段名称和类型一致。

必须正确处理 TCP 粘包、半包和连续消息。服务器应当根据连接分配玩家 ID，维护所有在线玩家，并在玩家移动或断开连接后更新其他客户端看到的玩家状态。

客户端不得直接修改其他玩家的最终位置，只负责发送自己的操作并显示服务器广播的状态。

## 7. 游戏规则

- 游戏区域建议为 800×600 像素。
- 每辆坦克使用简单的矩形和炮管绘制。
- 每个玩家使用不同颜色。
- WASD 控制移动方向。
- 坦克不能移动出游戏区域。
- 其他玩家的坦克由服务器状态同步更新。
- 玩家断开连接后，应从其他客户端的玩家列表和游戏画面中移除。

## 8. 服务器要求

服务端必须真实可运行，而不是模拟数据。

服务端需要实现：

1. TCP 监听。
2. 多客户端连接。
3. 玩家注册与 ID 分配。
4. 接收坦克移动消息。
5. 广播在线玩家状态。
6. 处理客户端断开。
7. 提供简单日志。

服务器使用简单的线程处理方式即可，不需要实现复杂的游戏引擎。

## 9. 验收标准

1. 服务端和客户端可以独立编译。
2. 客户端能够连接服务端。
3. WASD 可以控制自己的坦克。
4. 两个客户端能够同时连接。
5. 两个客户端能够互相看到对方的坦克移动。
6. 客户端断开后，其他客户端能够移除对应坦克。
7. 网络异常时界面不会卡死。
8. 项目无需下载额外图片素材即可运行。

## 10. 最终交付

请直接创建完整的 `TankBattle` 项目文件。

必须包含服务端源码、客户端源码、两个 pom.xml 和 README.md。

README 必须说明：

- 如何使用 Maven 编译。
- 如何启动服务器。
- 如何启动客户端。
- 如何运行两个客户端进行联机测试。
- 客户端五个核心类分别负责什么。

不要只提供代码片段，不要使用占位实现。

优先保证最小版本能够成功运行，再完善代码和注释。

所有客户端代码应适合 Java 初学者阅读，避免过度设计、复杂继承体系和不必要的设计模式。
